# Forever Command Center

GitHub Pages tracker for CoYo's World of Warcraft: Forever house.

Pick a character and the page shows that character's race, spec, professions, talent notes, and any stats from the Google Sheet. Hunt and task checks live on that sheet too, one column per character. If the sheet does not load, the page uses `data/stats.json` and `data/checklist.json` and does not keep new checks. Checks saved in a browser before the sheet were left behind.

## Update the site

- New hunt: add a row on the Hunts tab of the Google Sheet. `data/checklist.json` is the offline fallback, so keep that file in step when you want the page to still show the hunt if Google is down. Give it (or a piece) `"mobs": ["Boss Name"]` when the drop source is known, and the hunt shows KillDex kill counts for those mobs. Parked future drops use `"status": "Parked"`.
- Names, specs, professions: edit `data/characters.json`. A new roster id also needs a Config row and a checkbox column. See `scripts/sheets/SCHEMA.md`.
- Character numbers: run the scan, then paste the character JSON into the sheet's Import tab (or POST it). The live page reads the sheet. `data/stats.json` is only the fallback. Pasting the in-game `/dossier` text does not fill the sheet. The scan's JSON does, because that file includes bags, recipes, kills, and finished quests.
- Nightly: type `/dossier` in game, press Create Export, copy the text, and paste it into Cursor. The `nightly-export` skill saves it as `exports/beta/<first>-<last>-YYYY-MM-DD.txt`, runs the scan below, and opens a PR. Older CharacterExport dumps already in `exports/` still merge. After the scan, paste the new `data/exports/<name>-<date>.json` into the sheet Import tab so the live page updates without waiting on that PR.
- Dossier addon (called AIExport before 2.0.0): the source lives in `addon/Dossier/`. Edit it there, then run `powershell -File scripts/package-addon.ps1`. That writes `dist/Dossier-<version>.zip` for CurseForge and copies the addon into the `addonsPath` from `scripts/addons.local.json`. The first time, it also copies each character's `AIExport.lua` save to `Dossier.lua` (through `scripts/migrate-to-dossier.ps1`, which stops if the game is open) and moves the old `AddOns\AIExport` folder to `dist/AIExport-backup`. Restart the game the first time, then `/reload` after later builds. `/dossier help` shows the player guide.
- Dossier logo: the master image is `addon/art/logo-master.png`. Run `powershell -File scripts/make-addon-art.ps1` after changing it to rewrite `Media/Logo.tga`, `Media/MinimapIcon.tga`, and `dist/curseforge-logo.png` (the CurseForge project avatar, uploaded by hand).
- Biography: Dossier records level-ups, deaths, zones, quests, achievements, profession gains, and screenshots in each character's `Dossier.lua` save (`AIExport.lua` before 2.0.0; the scan reads either). The scan copies every event into `data/biography/<id>.json` and keeps the lines it already has. Screenshot events let the scan fill in `who` on matching entries in `data/screenshots.json`.
- Installed addons and a fresh Dossier merge: copy `scripts/addons.example.json` to `scripts/addons.local.json`, set `addonsPath` to your `Interface\AddOns` folder, then run `powershell -File scripts/scan-addons.ps1`. Commit `data/addons.json` when the addon list changes. The scan also writes `data/stats.json`, which is the fallback if the Google Sheet does not load. The scan reads the Syndicator, Profession Master, AllTheThings, Nova Instance Tracker, KillDex, and Questie saves, so bag items, recipes, kills, and finished quests reach the character JSON without their in-game export buttons. Log out or `/reload` first so the saves are written. Paste that JSON into the sheet when you want the live page to show it.
- Quests: when Questie and QuestieDB are installed, the scan writes finished quest ids onto the character and the name catalog into `data/quests.json` for the Quests tab. That list is quests already turned in. The quests still in the log are not in the save.
- Dungeons: when Forever Dungeon Journal is installed, the scan copies its bosses, drops, and quests into `data/dungeons.json` for the Dungeons tab. That data ships inside the addon, so it refreshes when the addon updates. Hunts whose item appears in the journal show which boss drops it.
- Library books: `data/library-books.json` holds every book spot, with coordinates and the zone map number, for the Library books section on Hunts. Run `powershell -File scripts/library-books.ps1` to refresh it from the [Zockify guide](https://www.zockify.com/forever/library-books/). Turn-in checks are a row per book title on the Hunts tab, one checkbox per character. The same title shares one row.
- Macros: add an entry to `data/macros.json` with `name`, `icon` (the Wowhead icon name, such as `inv_misc_coin_01`), and `lines`. Use `"scope": "shared"` for account macros, or `"scope": "character"` with `"character": "<id>"` for a single character's macro.
- Screenshots: Dossier's Screenshotter (or Memento) saves them in the game's `Screenshots` folder, and the scan logs new ones in `data/screenshots.json`. Biography screenshot events fill in `who`, and Screenshotter shots also fill in `caption` from the reason ("Reached level 12"). Set `who` and `caption` by hand on anything left (the nightly skill does this by reading the name over the player's head), then run the scan again. Roster characters' shots are copied to `assets/shots/<id>/` as `YYYY-MM-DD_HHMM_Character-Name_reason.jpg` and show in their card. A full-size copy with the same name goes to `<game>\Screenshots\Dossier\` (older copies in `Screenshots\AIExport\` move there on the next scan). The game's original files are never renamed.

The older roster page, farm workbook, and dashboard snapshot stay in the repo as source notes.
